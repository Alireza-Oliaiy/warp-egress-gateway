# Architecture

## Data plane

Packets arriving on `TRANSIT_IF` are evaluated after the kernel local table. Traffic addressed to the gateway itself remains local. Forwarded packets enter the configured policy-routing table and receive a default route through `WARP_IF`.

```text
TRANSIT_IF -> ip rule iif -> table 100 -> default dev WARP_IF
```

The WARP UDP transport itself is generated by the host and follows the main table through `UPLINK_IF`, preventing recursive routing into the tunnel.

## NAT

nftables masquerades only packets matching both:

- `oifname WARP_IF`
- `ip saddr TRUSTED_SOURCE_CIDR`

Reply translation is maintained by conntrack.

## Kill switch

The kill switch matches every packet entering `TRANSIT_IF` whose selected output interface is not `WARP_IF` and drops it before any established-state acceptance.

This ordering matters: if WARP disappears and Linux falls back to the main default route, existing connections are still blocked from `UPLINK_IF`.

The firewall is a separate systemd service. Stopping the tunnel or routing service does not remove the firewall table.

## Management plane

The host main default route remains unchanged:

```text
UPLINK_IF -> UPLINK_GATEWAY
```

Only traffic sourced from the WARP interface address and traffic entering `TRANSIT_IF` uses the WARP table.

## Boot ordering

1. Network becomes online.
2. Persistent firewall and kill switch load.
3. `wg-quick@WARP_IF` starts.
4. Policy-routing rules and WARP default table load.
5. Health timer begins checks.

## Deployment editions

### Native

The firewall, WireGuard interface, policy routing, and health services are installed directly on Ubuntu and ordered by systemd.

### Docker

The container shares the Linux host network namespace and operates the same host interfaces, routes, WireGuard interface, and nftables data plane. A separate host systemd guard loads before Docker and blocks transit fallback independently of container state.

```text
host guard -> Docker container -> warp0 and policy routing
```

The Docker edition is operationally containerized, but it is not network-isolated from the Linux host because a transparent gateway must control the host Layer-3 path.
